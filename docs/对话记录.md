## 一、项目定位（最终形态）

一个**静态网页（HTML+CSS+JS，无需后端）**的高股息股票观察池 + 投资决策辅助工具：

- 52 只 A 股（已剔除港股/美股），均为"常年分红"标的，预期股息率 ≥ 5%。
- 实时行情（腾讯接口）、实时自动每股分红（东财 datacenter）、K 线图（ECharts）。
- **V1.3 决策引擎**：买/卖分层阈值 + 迟滞 + 双闸门（基本面 🟢/🟡/🔴 + expDps 确认态）。
- 特殊分红标注（东财缺数据，用 westock 文件补 2 只）。
- 多端同步：应用内 GitHub 云端同步（Contents API）+ 命令行 git。

**状态：V1.3 已冻结**，停止加功能，按季度积累数据即可。

## 三、关键技术决策与发现

### 3.1 CORS（核心约束）
- ✅ 腾讯 `qt.gtimg.cn`：`Access-Control-Allow-Origin: *`，浏览器可直接抓实时行情。
- ✅ 东财 datacenter 报表接口：有 `Access-Control-Allow-Origin: *`，浏览器可实时抓普通分红。
- ❌ 东财 emweb（F10 分红明细）：**无 CORS**，浏览器 fetch 被拦；但 Node/curl 能取（故 westock/MCP 可用）。

> 结论：**实时 AutoDPS 走 datacenter（浏览器直连）；特殊分红走 westock 文件（由 MCP 季度刷新）**。

### 3.2 Auto DPS vs Forward DPS（概念不可混）
- **Auto DPS** = TTM 实际分红（向后看，实时可算）。
- **Forward DPS** = 已确认的、可持续的未来分红（估值锚点，需人工/半自动确认）。
- 决策引擎以 Forward DPS 为估值基准，未确认时降级为"待复核"。

### 3.3 决策引擎 V1 → V1.3
- **V1**：基础买/卖阈值。
- **V1.1**：买卖迟滞（买 5/6/7/8%，卖 ≤4.2%/清 ≤3.8%，避免抖动）；基本面+expDps 双闸门。
- **V1.2**：信任层——expDps 确认日期 + 自动过期；基本面日期 + 理由。
- **V1.3**：结构化基本面检查（6 项 + 重大事件否决）；Auto/Forward DPS 明确拆分。冻结。
- 阈值含义澄清：5/6/7/8% 是**执行分层**，非估值本身；资源/周期股整体 +2%。

### 3.4 特殊分红问题（结构性）
- 特殊分红 = 非报告期额外派息，**无 REPORT_DATE 字段**，东财 datacenter 表结构中不含 → 浏览器端实时取不到。
- 已确认有特殊分红的标的：`sh600219 南山铝业(0.2584)`、`sh600803 新奥股份(0.22)`。
- 方案：westock 文件维护特殊分红映射，季度用 MCP 刷新。

### 3.5 同步架构
- **应用内云端同步**：GitHub Contents API（Fine-grained PAT，Contents: Read/Write），按相对路径读写 `data/watchpool.json`。位置无关。
- **命令行 git**：仓库 `LylLLII/sustainable-dividend-watchpool`，`main` 分支。
- **差异合并**：repo 基准 + localStorage 的 added/removed/custom 差异。

## 四、踩过的坑与修复

1. **刷新空白** → 缓存 + 重试 + 东财兜底。
2. **BANDS 编辑时被删** → 重新加回。
3. **拉取云端 404** → 私有库缺 auth header，修 `ghHeaders(true)`。
4. **AutoDps 只显示 TTM 反推（1 分钟）** → 根因 emweb 无 CORS（浏览器拦）；且死代码兜底（`Promise.all` 永不 reject）；westock 文件仅 19 只 → 改 westock 为主 + datacenter 覆盖 + 重建 52 只文件。
5. **特殊分红缺失** → datacenter 不含 → westock 补；后升级 datacenter 实时 + westock 补特殊。
6. **用户纠偏**：固定 5/6/7/8 不是估值（保留为执行分层）；买卖阈值重叠（加迟滞）；expDps 未确认不能强买（闸门降级待复核）；基本面应自动过期（加复核日期）；Auto/Forward 混淆（拆分概念）。
