TTM 窗口偏移分析：JS subDaysStr(t, 365) 使用 setDate() 计算出 lo = 2025-08-06，Python timedelta(days=365) 计算出 lo = 2025-08-07，存在 1 天偏移。但 125 对年度分红中无任何一对在再平衡日（月初首个交易日）精确命中边界，因此偏移不影响任何回测结果。validate_engine.mjs 的逐位匹配证实了这一点。
阻断 P1conservative 模式完全缺失
Python target_weight() 有 gate_ok 参数：当 gate_ok=False 时不允许新买入（y ≥ buy 也只返回 "hold"），y < buy 直接返回 0.0。JS targetWeightPure() 完全未实现此参数，simulate() 也无 conservative 模式分支。对默认结果无影响（默认等价于 optimistic），但如果需要保守回测则无法使用。
修复方向：在 targetWeightPure 增加 gateOk 参数，在 simulate 增加 conservative 配置项，计算 gate_ok = ttm ≥ ttmDps(divs, subDaysStr(d,365)) × 0.99
重要 P2targetWeightPure 档位硬编码 vs targetWeightPct 参数化
targetWeightPure 使用硬编码 buy = isRes ? 7 : 5，而 targetWeightPct 使用 P.buyYield 和 P.resourceExtra。当 usePercentile=false 时，用户修改 buyYield 滑块不会生效。
修复方向：将 targetWeightPure 也改为参数化，或在 UI 标注"buyYield 仅百分位模式生效"

九、最终评审结论

结论：需修复后交付

工具核心功能完备、数据准确、引擎移植忠实、交互健壮。但存在 1 项阻断级问题需处理后才能达到完整交付标准。

维度评分判定关键依据
① 引擎移植保真度B+需修复optimistic 逐位匹配；conservative 缺失
② 策略逻辑合理性A−通过11 项逻辑全部与策略定义一致
③ 数据管道完整性A通过16/16 标的零差异，3 只抽样逐条一致
④ 交互界面与可视化B+需优化12/12 控件绑定；缺输入校验和基准标注
⑤ 边界情况与健壮性A−通过16 个边界场景全部通过
⑥ 可复现性与交接A通过一键启动，无额外依赖，校验脚本可独立运行
上线前必须修复的阻断项清单：
  1. P1 — conservative 模式缺失：如果工具仅用于 optimistic 回测（当前默认），可降级为"重要"并在文档中标注限制；如需完整对齐 Python 功能，必须补齐 gate_ok 闸门逻辑。
建议交付前处理的项：
  1. I-1 — 添加 sellYield ≥ buyYield 的输入校验（5 分钟工作量）
  2. I-2 — 在图例标注"基准为价格指数，不含分红"或在数据中补充基准 divs
  3. P2 — 在 UI 标注"buyYield 仅百分位模式生效"或将 targetWeightPure 参数化
