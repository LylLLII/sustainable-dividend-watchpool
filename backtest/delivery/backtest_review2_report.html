TTM 偏移修复验证 根因与修复
修复确认subDaysStr 现返回正确日期
修复前：new Date('2026-08-07'+'T00:00:00') 按 UTC 解析，setDate 按本地时区算 → subDaysStr('2026-08-07', 365) = '2025-08-06'（差 1 天）
修复后：改用 Date.UTC(y, m-1, d) + n × 86400000 毫秒算术 → subDaysStr('2026-08-07', 365) = '2025-08-07'（与 Python timedelta(days=365) 一致）
影响：百分位 30/70 的 CAGR 从修复前的 6.65% 变为 8.31%——之前的 6.65% 因 TTM 窗口多含 1 天旧分红，导致部分股票股息率偏高/偏低，影响了买入信号触发。修复后数值更准确。
resourceExtra 回归修复验证 根因定位
根因确认resourceExtra 逻辑错误是 CAGR 暴跌的真正原因
错误代码：const buy = P.resourceExtra ? P.buyYield + 2 : P.buyYield — 当 resourceExtra=true（默认）时，所有股票的买入线都变成 7%，非资源股（银行、电力等）从 5% 抬高到 7%，大量买入信号被过滤，仓位严重不足。
修复后：const buy = (isRes && P.resourceExtra) ? P.buyYield + 2 : P.buyYield — 只有 isRes=true 且 resourceExtra=true 时才 +2，与 Python (7,8,9,10) if is_res else (5,6,7,8) 逻辑一致。
验证：修复后 optimistic CAGR 从 13.11% 恢复到 16.03%，与 Python 逐位匹配。
